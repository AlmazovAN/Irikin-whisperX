# P08 — проверка входных аудиофайлов

**Этап 1 / Чат 02 / P08.** Самостоятельный stdlib-only модуль `modules/jobs/inputs.py`.
Фактический приём заданий, постоянное копирование исходника и очередь будут в P13–P15.
P08 не подключает новый UI и не переписывает старые обработчики Gradio/FastAPI.

## Контракт для следующих PR

```python
from modules.jobs import InputSource, validate_input

# Настройки доступа задаёт локальный сервер, а не браузер/параметры формы.
validated = validate_input(
    InputSource.upload(gradio_file_path, original_name="meeting.m4a"),
    upload_roots=[trusted_gradio_upload_directory],
)
# или
validated = validate_input(
    InputSource.local_file(user_chosen_local_path),
    local_roots=[server_approved_recordings_directory],
)
# validated.path / .safe_filename / .storage_filename / .duration_seconds
```

- `InputSource`: `upload`, `local_file` и зарезервированный `google_drive_url`.
  URL пока возвращает `SOURCE_NOT_SUPPORTED`, сетевых загрузок нет. P26 расширит адаптер.
- `validate_input(...)`: разрешает только путь внутри **явно переданных сервером**
  доверенных каталогов соответствующего типа. По умолчанию разрешённых каталогов нет.
  Символические ссылки проверяются после разрешения целевого пути; весь диск как
  разрешённый корень не допускается. Это не веб-файловый менеджер общего назначения.
- Разрешены только расширения `.wav`, `.mp3`, `.m4a`, `.ogg` без учёта регистра.
  Проверяются непустой размер, порог по размеру (по умолчанию 512 MiB), наличие
  аудиопотока и длительность через внешний `ffprobe` (по умолчанию не более 4 часов).
  `ffprobe` запускается без shell, с ограничением времени 15 секунд.
  Медиа с видеопотоком и повреждёнными/недостаточными метаданными отвергаются.
- Возвращается `ValidatedInput` с разрешённым `Path`, безопасным читаемым именем,
  уникальным `storage_filename`, размером, длительностью и кодеком. Имя отделено
  от директории, нормализуется под Windows, сохраняет кириллицу и расширение.
  Ошибки имеют машинный `InputValidationError.code`, сообщения не раскрывают
  системные пути, внутренний вывод FFprobe или приватные данные.
- Проверка метаданных **не гарантирует декодирование каждого фрейма**. P09/P11
  обрабатывают диагностируемые ошибки декодирования/ASR; P14 повторно проверяет
  источник при копировании в постоянный `data/jobs/<uuid>/input/`, поскольку
  между проверкой и копированием временный файл может измениться/исчезнуть.

## Матрица проверок

`python -m pytest -q tests/unit/test_job_inputs.py` — офлайн, без моделей.
В лёгком CI без FFprobe реальные media-тесты помечаются `SKIP`, а имитационные
проверки политики, форматов, метаданных, timeout и безопасности путей выполняются.
На машине с FFprobe/FFmpeg дополнительно используются сгенерированные тестовые
WAV/MP3/M4A/OGG, никакие пользовательские записи в Git не помещаются.

Проверки безопасного приёма не означают, что текущие legacy UI/API уже используют
этот слой: переключение интерфейса на JobService запланировано в P14–P21.
