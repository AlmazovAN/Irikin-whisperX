# P06 — ручной smoke-test текущего WhisperX-конвейера

**Дата подготовки:** 2026-10-16.
**Состояние фактического прогона:** `NOT_RUN` на целевом Windows-ПК.
Код этой проверки и автономные unit-тесты добавлены, но здесь
**нет результата настоящей транскрибации**. Пользователь планирует
проводить ручную приёмку после готовности MVP; тест можно отложить.

## Что именно испытываем

Унаследованный `WhisperXInference.run()` и
`WhisperXWrapper` (без второго конвейера):
`VAD → WhisperX Small ASR → alignment → Pyannote diarization`.

| Параметр | Значение |
| --- | --- |
| Модель | `small`, другая запрещена в P06 |
| Язык | `ru` (Russian в UI-конвертере старого pipeline) |
| Задача | `transcribe`, не translate |
| Устройство | `cpu` по умолчанию для AMD Radeon iGPU |
| Compute type | `int8`, batch 1 по умолчанию |
| VAD | Включён |
| Alignment | Включён, требуются word timestamps |
| Diarization | Включена по умолчанию, требуется хотя бы одна метка `SPEAKER_*` |
| Формат | Локальный WAV/MP3 длительностью до 90 с, объём до 25 MiB |
| UVR/Translation | Отключены |

Нужна *реальная* небольшая запись русской речи, предпочтительно
5–30 секунд (если нужно проверить разделение **двух** спикеров —
две различимые реплики). Запись остаётся на ПК. Не добавляйте
реальный аудиофайл, стенограмму или токен в Git/PR.

## Проверка без моделей, файлов и ручной приёмки

Из корня репозитория, **после установки P03**:

```bat
venv\Scripts\python.exe scripts\smoke_whisperx.py --diagnose-only
```

Это проверка уже установленного окружения через P02: Windows,
FFmpeg/FFprobe, Python, установленные пакеты, torch/CUDA и
наличие HF-токена. Команда **не скачивает модели**, не открывает
браузер, не обрабатывает аудио и не подтверждает работу inference.

Наличие пакета в метаданных и положительная диагностика
PyTorch/HF_TOKEN **не доказывают** доступ к gated Pyannote-модели.

## Настоящий запуск (можно отложить до MVP)

1. Установить зависимости через P03 (CPU-профиль для AMD).
2. При необходимости диаризации отдельно оформить доступ
   к Pyannote-моделям на Hugging Face, принять их условия
   использования, разместить свой `HF_TOKEN` в приватном `.env`
   в корне репозитория; токен не помещать в команды, тикеты,
   публичные файлы или чаты.
3. В отдельной консоли, когда **Start.bat и другой inference не работают**:

```bat
venv\Scripts\python.exe scripts\smoke_whisperx.py --audio "C:\audio\short_russian.wav"
```

Вариант с MP3:

```bat
venv\Scripts\python.exe scripts\smoke_whisperx.py --audio "C:\audio\short_russian.mp3"
```

Первый запуск **может скачать большие веса моделей**, потребовать
сетевой доступ, продолжаться длительно на CPU и упереться в 8 ГБ RAM.
Это самостоятельное *явное* действие, не часть `Start.bat`
или `--diagnose-only`.

Для отладки ASR + alignment **без Pyannote**, если пока нет доступа:

```bat
venv\Scripts\python.exe scripts\smoke_whisperx.py --audio "C:\audio\short_russian.wav" --without-diarization
```

Даже если ASR и alignment работают, такой прогон возвращает
**`PARTIAL`**, а не `PASS`. На оборудовании с реально обнаруженной
совместимой NVIDIA GPU возможен `--device cuda`; не применять на
AMD Radeon как эквивалент CUDA.

## Интерпретация отчёта

Файл `logs/smoke-YYYYMMDDTHHMMSSZ-XXXXXXXX.json` пишется
атомарно. Он содержит техническую информацию, **но не аудио,
полученный текст, полный путь файла или значение HF-токена**.

| Статус | Exit code | Значение |
| --- | ---: | --- |
| `ready_for_manual_audio` | 0 | Только диагностика; модель НЕ запускалась |
| `blocked` | 2 | Нет необходимого компонента, токена, устройства или правильного файла |
| `failed` | 1 | Ошибка реального запуска или неверный/пустой результат |
| `partial` | 3 | ASR + alignment подтверждены, но диаризация пропущена |
| `passed` | 0 | **Только** настоящий прогон с текстом, word timestamps и speaker labels |

Признаки успеха: `actual_inference_performed=true`,
`metrics.asr_verified=true`,
`metrics.alignment_verified=true`,
`metrics.diarization_verified=true`. Проверка требует хотя бы одну
метку говорящего; оценка **точности** разделения двух говорящих
потребует отдельной аудио-разметки при MVP.

`stages.vad=enabled_not_independently_verified` показывает, что
VAD был включён в конфигурации, но данная диагностическая утилита
не делает независимого утверждения о правильности VAD.
Для полноценного QA требуются короткие и длинные файлы,
тишина, два спикера, русские реплики и сравнение с эталоном.

**Важно:** сообщение `FAILED` содержит только класс ошибки,
без потенциально секретного текста исключения. Для расследования
запуска смотрите локальные журналы и обезличивайте их перед передачей.

## Тесты без тяжёлых библиотек

```bat
venv\Scripts\python.exe -m pytest -q tests/unit/test_smoke_whisperx.py
```

Эти тесты создают поддельные данные сегментов и подменяют
устройство/HTTP/вызов inference. Они доказывают только корректность
правил принятия решения, не работу WhisperX/Pyannote на Windows.

Проверки acceptance на целевом ПК, когда MVP готов:
`Install.bat --profile cpu --dry-run`,
`Start.bat --check-only`,
`python -m pip check`, `--diagnose-only`, полноценный WAV/MP3
smoke, затем UI с сохранением TXT/JSON, закрытием вкладки и
повторным открытием задания. Последние UI/job-сценарии будут
реализованы в P07–P25, а не в P06.

## Известные ограничения

- P03 пины пока кандидатные; полного transitive lock нет.
- На 8 ГБ RAM Small + alignment + Pyannote могут не поместиться:
  конкретный OOM/несовместимость нужно зафиксировать, а не
  выдавать скрипт за подтверждение работоспособности.
- Факт наличия токена не подтверждает права доступа к gated
  модели; это проверяет только реальный вызов.
- Старый `BaseTranscriptionPipeline.run` кэширует настройки
  в `configs/default_parameters.yaml`; P04 удаляет секреты
  перед записью, но настоящую изоляцию per-job нужно сделать в P07.
- Smoke P06 намеренно **не пишет** финальный transcript TXT/JSON
  и не создаёт долговременные задания — это ответственность MVP.
- Решение о единственном worker зафиксировано в
  [ADR-001](adr/ADR-001-single-worker.md). Наличие ADR не означает,
  что worker уже реализован.
