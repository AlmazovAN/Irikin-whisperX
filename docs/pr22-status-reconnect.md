# PR22 / roadmap P21 — статус, прогресс и восстановление вкладки

База: `master` после GitHub PR #21, SHA `7751b3ee71d7915ad8441e96656314ae5c40cd28`.
Ветка: `feature/p21-status-reconnect`.

## Изменения

- Simple Mode добавляет поля **Этап обработки** и шкалу контрольных точек.
- Статус считывается по UUID из `JobService.get_status()` при открытии страницы (`Blocks.load`) и раз в 2 секунды (`gr.Timer.tick`). Каждое обращение выполняет новый SQLite SELECT, а не читает память вкладки.
- Единственный UUID текущего задания сохраняется в `gr.BrowserState` (`localStorage` браузера). Постоянные `storage_key` и `secret` дают возможность восстановления после reload, закрытия/открытия вкладки и перезапуска локального сервера на том же host:port. Это **не токен авторизации**: в браузере не сохраняются стенограмма, исходный путь, токен HF или аудио.
- При неудачной отправке нового файла сохраняется UUID ранее принятого задания.
- `queue=False` для запросов состояния: они не занимают очередь интерфейсной обработки; worker и тяжёлая модель остаются независимо от вкладки.
- Отображаются состояния QUEUED, IN_PROGRESS, COMPLETED, FAILED, INTERRUPTED, CANCELLED. Для `CANCEL_REQUESTED` показано ожидание безопасной точки отмены; для FAILED — диагностический код при наличии.
- Ошибочные UUID не отражаются обратно в интерфейс, приватные исключения SQLite и пути файлов не показываются. Неизвестный UUID не подбирается из истории другого задания.

## Семантика процентов

Шкала 0–100 — **условный индикатор стадий**, а не процент затраченного времени, скорость обработки или ETA. Worker сохраняет значения по P16:
QUEUED/PREPARING 0; VAD 3; ASR 12–70; ALIGN 72; DIARIZE 85; EXPORT 95; DONE 100.
При ошибке или прерывании шкала показывает последнюю достигнутую точку.
Во время вычисления ASR показатель может не двигаться долго, затем измениться скачком.
Переход к 100 возможен только при `COMPLETED`, который ставится после атомарного сохранения артефактов.

## Восстановление и ограничения

1. `Start.bat` → Simple → загрузить файл → «Начать обработку» → увидеть UUID/состояние.
2. Свернуть, закрыть или перезагрузить вкладку. Локальный Python и ПК должны продолжать работу.
3. Открыть **тот же localhost host:port и профиль браузера**: сохранённый UUID восстанавливается и последующий polling показывает актуальный статус из SQLite.
4. Если сервер действительно перезапускался во время ASR, код восстановления P18 переводит задачу в INTERRUPTED (или подтверждённый COMPLETED). Возобновление инференции с середины не реализовано.
5. Очистка localStorage/смена браузера/порт или host могут потерять сохранённый UUID; сама задача и аудиофайл остаются в SQLite/локальной папке. История и выбор предыдущего задания — P24.
6. В P21 **нет** скачивания TXT/JSON, отдельного REST API, истории, новых моделей, автоматического retry или принудительной остановки GPU. Они не добавляются в этом PR.
