# P24 / GitHub PR #25 — мини-история, предпросмотр и безопасное удаление

База: `master` после P23 / GitHub PR #24, `986ad007cc8974e05e9cfc73bda859aafa364e83`.
Ветка: `feature/p24-history-preview-cleanup`.

## UI и сохранность

- В Simple Mode появилась история последних **30** заданий, отсортированная по времени добавления в SQLite (новые сверху). Отображаются дата, имя файла, статус и модель. Список запрашивается через уже готовый `JobService.list_jobs(limit=30)` — новые таблицы/миграции не нужны.
- История загружается после открытия страницы и обновляется кнопкой «Обновить историю», а также после успешного добавления файла. Выбор задачи меняет `BrowserState` текущего UUID, восстанавливает статус и ссылку скачивания, но **не запускает ASR** повторно.
- Предпросмотр показывает начало **проверенного** файла `transcript.txt`; чтение ограничено 12 КиБ. Для незавершённого/повреждённого задания текст не показывается. Полный TXT по-прежнему скачивается через существующий `DownloadButton`.
- «Открыть папку результата» использует проверенный `JobService.get_artifact(uuid, format="txt")` и `os.startfile` на локальном Windows-хосте. Пользователь не передаёт произвольный путь из браузера; на других ОС действие сообщает об ограничении.
- Настройки модели, WhisperX, worker, параметры ru и JSON/TXT schema не изменены.

## Удаление с явным подтверждением

В интерфейсе есть checkbox «Подтверждаю безвозвратное удаление…» и отдельная кнопка удаления. Просто выбрать запись или обновить список **недостаточно**. Checkbox сбрасывается после попытки удаления и при выборе другого задания.

`JobService.delete_terminal(uuid, confirmed=True)`:

1. Проверяет канонический UUID и подтверждение.
2. Начинает SQLite `BEGIN IMMEDIATE`, повторно проверяет статус под блокировкой. Удаление допустимо **только** для `COMPLETED`, `FAILED`, `CANCELLED`, `INTERRUPTED`. `QUEUED` и `IN_PROGRESS` блокируются даже если браузер показывает устаревшее состояние.
3. Проверяет каталог `data/jobs/<uuid>`; отказывает при symlink/junction, отсутствующей папке и ранее созданной карантинной папке. Затем переименовывает только выбранный UUID-каталог в `data/jobs/.deleting-<uuid>`.
4. Удаляет строку этого UUID из SQLite и коммитит. При отказе транзакции делает rollback и возвращает исходное имя каталогу. Никаких рекурсивных удалений родителя или других UUID не выполняет.
5. После успешного коммита очищает карантинный каталог. Если файловая система отказала, возвращает `DELETE_CLEANUP_PENDING`: запись удалена, но приватные файлы могут остаться в карантине для ручного вмешательства. Это не «полностью удалено».

Особенность: SQLite + filesystem **не дают единой атомарной транзакции** на случай жёсткого отключения питания между rename и COMMIT. При таком редком сбое может остаться `.deleting-<uuid>`; его нельзя удалять автоматически без сверки с SQLite. В P25 вручную проверить и описать восстановление.

Никакая автоматическая очистка по возрасту записи не добавлена. Удаление доступно **только по явному действию**. Открытая ранее ссылка на TXT может сохраняться в cache Gradio или папке загрузок браузера: это не гарантированное удаление всех пользовательских копий.
