# PR17 / P16 — этапы обработки и сохранённый прогресс

База: master после PR16, SHA \`48fba5a5940c9925a477e623ccbd319c16bf2b16\`.
Ветка: feature/pr17-persisted-stage-status.

## Фактические события

В legacy BaseTranscriptionPipeline.run() уже есть сообщения:
\`Filtering silent parts from audio..\`, \`Transcribing with WhisperX..\`,
\`Aligning with WhisperX..\`, \`Diarizing speakers..\`.
HeadlessProgress в PR17 распознаёт **только эти сообщения** и передаёт
соответственно VAD / ASR / ALIGN / DIARIZE. Остальные сообщения игнорируются,
никакой произвольный текст из модели/аудио не сохраняется.

Из WhisperXWrapper поступает \`progress_callback(value)\` со значениями
приблизительной доли **обработанного аудио в ASR**. Это не доля всей
многоэтапной работы. Worker переводит такие значения в условную шкалу:

| Текущий этап | Минимальное значение Task.progress |
| --- | ---: |
| QUEUED / PREPARING | 0.00 |
| VAD | 0.03 |
| ASR | 0.12 — 0.70 по прогрессу ASR |
| ALIGN | 0.72 |
| DIARIZE | 0.85 |
| EXPORT | 0.95 |
| COMPLETED / DONE | 1.00 |

Шкала — **индикатор контрольных точек**, не оценка оставшегося времени.
Этапу EXPORT присваивается статус непосредственно перед записью JSON/TXT.
COMPLETED / 100% устанавливается только после успешного экспорта.
При FAILED достигнутая отметка сохраняется; после явного retry сбрасывается
в 0. На текущем этапе не создаются фиктивные временные метки или ETA.

## SQLite, UI и гонки

- \`JobService.get_status(uuid)\` и прежний \`get(uuid)\` выполняют
  **новый SQLite SELECT для каждого обращения**. Можно опрашивать из
  новой вкладки браузера/сессии либо нового экземпляра сервиса.
  \`list_jobs()\` также возвращает свежий прогресс.
- \`JobTicket\` расширен безопасными полями \`progress\`, \`updated_at\`,
  \`started_at\`, \`finished_at\` и сохраняет совместимость старых конструкторов.
  Приватные пути, HF_TOKEN и тексты исключений не включаются в результат.
- Worker проверяет \`status='IN_PROGRESS'\`, UUID и \`attempt\` внутри
  транзакции BEGIN IMMEDIATE. Значение может только увеличиваться в
  рамках текущей попытки. Запоздавшие события от предыдущего этапа/попытки
  не способны переписать новое состояние.
- Новая миграция БД не требуется: используются поля \`stage\`, \`progress\`,
  \`started_at\`, \`updated_at\` из P13 и прежней Task модели.

## Ограничения

- В этом PR не добавлен REST/FastAPI-endpoint и не изменён старый UI.
  Подключение нового простого Gradio-интерфейса выполняется позднее,
  с обязательным устранением второго владельца модели.
- Worker уже умеет запускать задания независимо от открытой вкладки;
  реальное закрытие Gradio-вкладки пока **не испытано**.
- Поддержка отмены уже выполняемого ASR, восстановление после аварийного
  рестарта и полностью атомарные артефакты остаются соответственно
  за P19/P18/P17 дорожной карты.
- Автономные тесты запускают SQLite/потоки, но не модели Pyannote/WhisperX
  и не Windows/CPU; статус аппаратной приёмки — NOT_RUN.
