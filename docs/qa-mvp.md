# P25 — итоговая приёмка локального WhisperX MVP

Дата подготовки: 2026-10-17. Репозиторий: AlmazovAN/Irikin-whisperX.
Основание: `master` после P24 / GitHub PR #25, SHA
`c578bd78778a565559385880c5ac05ce2776520f`.

## Статус: RELEASE BLOCKED — реальный Windows-прогон пока NOT_RUN

Этот документ **не** свидетельствует, что модель, Gradio или загрузка TXT
проверены на целевом компьютере. CI на GitHub использует Linux и фальшивые
ASR-модели. Релизный тег `v0.1.0-mvp` **нельзя** ставить до выполнения
приёмочных критериев ниже, анализа сохранённых отчётов и исправления
выявленных блокеров.

Целевая конфигурация владельца: Windows 11, Ryzen 5 5500U,
встроенная AMD Radeon, 8 ГБ RAM (7,34 ГБ доступно). В этом MVP предполагается
**CPU/int8, batch_size=1**, CUDA у AMD iGPU не ожидается. Работоспособность
Small+VAD+alignment+Pyannote при таком объёме памяти **не доказана**.

## Что можно проверять без тяжёлых моделей

GitHub CI (`python -m pytest -q tests/unit`) тестирует миграции SQLite,
очередь JobWorker, сохранение TXT/JSON, атрибуты
`COMPLETED/FAILED/INTERRUPTED`, работу фальшивого Gradio,
безопасное удаление и автономный QA-механизм P25.
`scripts/mvp_release_gate.py` проверяет полноту протокола и
по умолчанию возвращает **BLOCKED**.

Подготовленная QA-система **не** стартует WhisperX при запуске `--preflight`,
не скачивает модели, не копирует аудио в git-репозиторий и не удаляет
записи после испытаний.

## 1. Подготовить Windows

1. Обновить локальную ветку `master`, остановить `Start.bat`
   и убедиться, что другой WhisperX / Gradio сервер не выполняет ASR.
2. Проверить рабочий CPU-профиль из инструкции `docs/windows-installation.md`
   (`Install.bat --profile cpu`). Не перезаписывать существующий venv.
3. Убедиться, что работают `ffmpeg` и `ffprobe`. Настроить
   `HF_TOKEN` **локально** через окружение или игнорируемый `.env`.
   Gated-модели Pyannote требуют принятия условий владельцем аккаунта.
   **Не прикладывать токен, аудио или стенограмму к PR/отчёту**.
4. Выбрать три локальных файла: короткая русская речь (примерно 10–60 с),
   более длинная русская запись (несколько минут), запись с
   **двумя различимыми собеседниками** (с согласия участников).
   Избегать реальных секретов в тестовых записях.
5. Запустить read-only диагностику:

```bat
venv\Scripts\python.exe scripts\qa_mvp.py --preflight
```

Отчёт сохранится в локальный `logs/qa-mvp-*.json`, git его игнорирует.
Статус `PREFLIGHT_ONLY` означает **только наличие предпосылок**,
а не проверенную расшифровку. `BLOCKED` при отсутствии
библиотек/FFmpeg/токена следует устранить до прогона.

## 2. Реальная очередь, модели и 10 повторов

При выключенном Gradio-сервере (не запускать конкурирующий worker)
выполнить команду в папке репозитория:

```bat
venv\Scripts\python.exe scripts\qa_mvp.py --run --short "C:\QA\ru-short.wav" --long "C:\QA\ru-long.wav" --two-speakers "C:\QA\ru-two-voices.wav"
```

Пути в примере — условные; подставить реальные локальные файлы.
Скрипт использует **настоящий** `JobService`, `JobWorker`,
`TranscriptionService` и `get_artifact()` с проверкой SHA-256.
Запускает три входных записи и ещё **10 последовательных повторов короткой**.
В каждой попытке создаётся отдельный UUID. Worker один.

В каждом результате валидируются:
- `COMPLETED` и одна законченная попытка после реального вызова модели;
- JSON `schema_version=1`, `small`, `ru`, `diarization_requested=true`;
- хотя бы одно слово с таймкодами, хотя бы один размеченный спикер;
- **не менее 2 разных** меток speaker для двухголосной записи;
- полное совпадение строк TXT с нормализованными сегментами JSON;
- SHA-256 пары файлов в manifest и сохранность ранее созданных 13 результатов.

Отчёт `logs/qa-mvp-*.json` **не включает реплики, исходные пути,
текст стенограмм и токен HF**; приватные аудио и оригинальные результаты
сохраняются отдельно в игнорируемом `data/qa_mvp_runs/<run-id>/`.
Удалять их можно **только вручную после приёмки**.
Прерывание/таймаут/ошибка/отсутствие спикеров означает FAIL, не PASS.
При timeout отмена кооперативная; скрипт не обещает мгновенную остановку
занятой модели.

Если 8 ГБ RAM недостаточно (OOM, своп, прекращение Pyannote), результат
фиксируется как **FAIL/BLOCKED**. Не подменять тест облегчённым режимом
без диаризации, CUDA-тестом на другом ПК или облачной транскрибацией.

## 3. Браузерный ручной протокол

Запустить `Start.bat`, открыть `http://127.0.0.1:7860/`.
Результат каждой проверки должен быть **наблюдён**, а не выведен
из успеха unit-тестов. Регистрировать `PASS / FAIL / NOT_RUN`,
краткое замечание без приватной информации.

| ID ручного теста | Проверка / ожидаемый результат |
| --- | --- |
| windows_install_and_start | Start.bat, один локальный сервер, нет второй модели |
| browser_ru_short_completed | drag/drop + запуск + ру-текст + статус DONE |
| browser_long_audio_completed | длинная запись до конца, TXT не пуст |
| browser_two_speakers_confirmed | двое говорящих, раздельные метки в TXT/JSON |
| tab_minimized_survives | свёрнутая вкладка не прерывает worker |
| tab_closed_survives | закрытая вкладка, сервер и ПК работают, обработка продолжается |
| tab_reload_reconnects | F5/повторное открытие: тот же UUID, актуальный SQLite-статус |
| server_restart_recovery | рестарт во время ASR: INTERRUPTED или доказанный COMPLETED; без ложного успеха |
| offline_after_models_cached | после первого **онлайн** скачивания моделей — физически без сети, локальная обработка |
| manual_txt_download | Скачать TXT вручную после успешного задания и повторного входа |
| automatic_download_or_manual_fallback | автоскачивание или понятный fallback без потери результата |
| history_and_preview | история, повторный выбор и предпросмотр без повторной модели |
| open_folder_windows | кнопка открывает каталог именно выбранного результата |
| safe_delete_confirmation | без checkbox нет удаления; активная задача защищена; выбранная удаляется |
| failure_does_not_show_completed | отказ Pyannote/ошибка медиа даёт FAILED и код; никаких фиктивных 100% |
| no_duplicate_worker | второй сервер на том же хранилище не создаёт конкурирующую ASR |

**Перезапуск сервера** не означает продолжение ASR с прерванного места.
Проверяется честное состояние и сохранённый исходный файл; повторное
распознавание возможно только по явному запросу пользователя.
**Отключение питания при удалении** может оставить
`data/jobs/.deleting-<uuid>`, который следует сверить с SQLite и
обработать вручную, не стирая автоматически.

Для ручного протокола создаётся шаблон:

```bat
venv\Scripts\python.exe scripts\mvp_release_gate.py --template logs\mvp-manual.json
```

После реальной проверки вручную заменить `"NOT_RUN"` на `"PASS"`
только для пройденных тестов и заполнить `note` наблюдением.
Для блокера указать `"FAIL"` и комментарий. В файле нет необходимости
хранить имена людей, записи, токены или локальные пути.

## 4. Релизный gate

```bat
venv\Scripts\python.exe scripts\mvp_release_gate.py --evaluate "logs\qa-mvp-ИМЯ_ОТЧЁТА.json" --manual "logs\mvp-manual.json"
```

`BLOCKED` — если нет реального полного Windows-прогона
(13 успешных работ с JSON/TXT, включая 2 спикеров) **или**
хотя бы один ручной тест не подтверждён.
`READY_FOR_HUMAN_RELEASE_REVIEW` — файл протокола заполнен
и прошёл формальную проверку; это **не удостоверение подлинности
введённых наблюдений** и не GitHub release.

### Перед присвоением тега v0.1.0-mvp

1. Сверить файлы отчётов с локальным состоянием ПК и git SHA `master`.
2. Убедиться, что CI зелёный на конечном commit и нет открытых blocker issues.
3. Убедиться, что документы и артефакты не содержат личные записи/токены.
4. **Только после** подтверждения человеком можно создавать тег
   `v0.1.0-mvp` на проверенном commit через GitHub; скрипты не ставят тег.

При отсутствии доступа к целевому Windows-компьютеру состояние этапа:
**код QA и приёмочный протокол подготовлены, релиз НЕ подтверждён**.
