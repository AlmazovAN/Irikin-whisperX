# PR21 / P20 — Simple Mode, первая вкладка WhisperX

**База:** master после PR20: e04e6af5479de5a68b95a4c2c3731acca56c8ed2.
**Точка запуска на Windows:** Start.bat.
**Компоненты:** modules/ui/simple_mode.py, app.py,
scripts/launch_windows.py, tests/unit/test_simple_mode_ui.py.

## Что добавлено

По умолчанию Start.bat запускает Simple Mode через app.py --ui_mode simple.

Сценарий: открыть вкладку localhost → перетащить один WAV/MP3/M4A/OGG →
нажать «Начать обработку». После подтверждения серверная часть уже
сохранила исходный аудиофайл в data/jobs/<uuid>/input и зафиксировала
QUEUED в SQLite. На экране сразу отображаются ID задания и сообщение
«В очереди». Следующая версия P21 добавит опрос состояния из SQLite
и восстановление текущего задания после перезагрузки вкладки.

Настройки намеренно скрыты и фиксированы:
- модель Whisper Small;
- язык ru, задача transcribe;
- VAD + WhisperX alignment + обязательная диаризация;
- CPU/int8 как исходный профиль без предположений о CUDA;
- всегда только один владелец inference через JobWorker.

Веб-обработчик не вызывает WhisperX напрямую, только
JobService.submit(InputSource.upload(...)) и worker.wake().
Новый JobService принимает файлы **только** из заранее заданного
Gradio upload root, проверяет FFprobe, сохраняет копию до enqueue.
Не принимаются пути вне доверенной директории; подавляются внутренние
сообщения исключений, возвращаются стабильные коды ошибок.
У Gradio upload root в локальном сервере путь data/ui_uploads,
через переменную GRADIO_TEMP_DIR до импорта библиотеки.

## Legacy Advanced

Legacy вкладки File, Youtube, Mic, Live, Translation и BGM Separation
**не удалены**. В Simple Mode присутствует вкладка Advanced с
инструкцией перехода. Сам legacy UI включается **только после
остановки** Simple-сервера и запуска:

    Start.bat --ui-mode advanced

Это намеренное ограничение: legacy App.__init__ создаёт собственный
WhisperFactory и выполняет ASR напрямую. Загружать обе архитектуры
в одном процессе — риск двух независимых экземпляров модели.
Безопасный выбор режима выполняется на старте процесса:
- Simple: только JobWorker + JobService, legacy App не создаётся;
- Advanced: только старый App, новый JobWorker не стартует.

Режимы также доступны при прямом запуске:
    python app.py --ui_mode simple
    python app.py --ui_mode advanced

Оба режима ограничены loopback-only и запретом публичного share/API.

## Жизненный цикл

JobWorker.start() выполняется до открытия локального веб-сервера:
он проверяет межпроцессную блокировку и выполняет PR19 recovery.
Gradio callbacks работают только с очередью; закрытие вкладки
не останавливает worker. При завершении самого Python-сервера
используется JobWorker.stop(wait=True), который не прерывает
непосредственно обрабатываемый файл. Если процесс принудительно
убит, применяются сценарии PR19 восстановления.
