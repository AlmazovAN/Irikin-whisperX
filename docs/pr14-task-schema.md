# PR14 / P13 — Task schema and SQLite migration

Дата: 2026-10-16. Исходный master: bc869242ef1349912da3c321df9f18cfb63b53d7.

Этот PR реализует только P13 дорожной карты (GitHub PR #14).
Следующая задача P14 / GitHub PR #15 — долговременное сохранение входного аудио;
worker, статусы прогресса и retry относятся к последующим PR.

## Новые поля Task

| Поле | Смысл |
| --- | --- |
| stage | VAD, ASR, ALIGN, DIARIZE, EXPORT и другие этапы |
| attempt | Номер попытки, для старых записей 0 |
| input_path | Приватное расположение принятого аудиофайла |
| output_json_path, output_txt_path | Приватные пути артефактов |
| model_name, model_version | Фактическая модель и версия |
| started_at, finished_at | Время обработки |
| error_code | Машинный код ошибки |

Добавлен статус INTERRUPTED для будущей реализации восстановления.
Поля с приватными путями не передаются через TaskStatusResponse.

## Алгоритм миграции

- На новой базе создаётся схема tasks, совместимая с моделью SQLModel.
- На старой SQLite отсутствующие колонки только ДОБАВЛЯЮТСЯ. Ни одна старая запись не удаляется.
- Версия v1 хранится в whisperx_schema_migrations, выполнение идемпотентно.
- Миграция выполняется в транзакции; неподдерживаемая схема или будущая версия останавливают обновление.
- Для существующего файла migrate_task_database создаёт резервную копию SQLite перед модификацией.
- init_db запускает миграцию перед SQLModel.metadata.create_all для SQLite; другие СУБД не меняются.

Файл backend/records.db уже отслеживается Git. В PR он не изменён.
При реальном запуске legacy backend со старой SQLite рядом появится локальная резервная копия.
Не коммитить этот файл и резервную копию. Для будущего JobService используется
отдельная база data/jobs/jobs.sqlite3, не backend/cache и не legacy records.db.
